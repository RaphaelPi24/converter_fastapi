Проект представляет собой высокопроизводительный, асинхронный веб-сервис для конвертации файлов (видео, изображения, текст, архивы). Архитектура построена на **FastAPI** и использует **Redis Queue (RQ)** для вынесения длительных операций в фоновые воркеры, что обеспечивает высокую отзывчивость API.

## ✨ Ключевые инженерные решения

| Аспект | Используемая технология / Паттерн | Ценность для проекта |
| :--- | :--- | :--- |
| **Параллелизм и Отзывчивость** | **FastAPI** (ASGI) + **RQ** (Redis Queue) | Длительная конвертация выполняется асинхронно в отдельных воркерах, не блокируя основной API-сервер. |
| **Архитектура** | **Паттерн Миксинов** и **Selector** | Логика конвертации строго изолирована в классах-миксинах (`Image`, `Video`, `Text`, `Archive`). Это делает систему легко расширяемой и простой для юнит-тестирования. |
| **Развертывание** | **Docker Compose** (Dev/Prod) + Nginx | Конфигурации для быстрого запуска в разработке и масштабируемого развертывания в продакшене (с использованием отдельной сети и Nginx). |
| **Тестирование** | **Pytest** и модульное покрытие | Полное модульное покрытие для каждой функции конвертации, гарантирующее стабильность ядра системы (папка `tests_convertors`). |
| **Управление ресурсами** | RQ + Асинхронный `lifespan` | Автоматическая очистка загруженных и сконвертированных файлов по таймеру (5 минут) с использованием отложенных задач в RQ. |
| **Безопасность/Контроль** | **LimitUploadSizeMiddleware** | Внедрение Middleware для ограничения размера загружаемых файлов до 50 МБ (или согласно настройкам) для защиты от DoS-атак и перегрузки. |

## 🛠️ Технологический стек

* **Фреймворк:** FastAPI
* **Асинхронные задачи:** Redis Queue (RQ)
* **База данных:** PostgreSQL 17 (для аутентификации)
* **Кэширование/Брокер:** Redis
* **Контейнеризация:** Docker, docker-compose
* **Библиотеки конвертации:** Pillow, cairosvg, PyMuPDF (fitz), python-docx, reportlab, FFmpeg (через `subprocess`)

## 📂 Структура проекта

Проект использует архитектуру, основанную на доменном разделении (похожа на Чистую Архитектуру), что обеспечивает чёткое разделение ответственности:
.
├── build/                 # Конфигурации Docker (Dev/Prod) и скрипты запуска
├── infrastructure/        # Настройка БД (PostgreSQL), Redis и конфигурация
│   ├── db/
│   └── redis/
├── src/                   # Основной исходный код 
│   ├── auth/              # Роуты, модели и утилиты для аутентификации через токен
│   ├── converters/        # Ядро логики конвертации (классы Image, Video, Selector)
│   └── main.py            # Точка входа: роуты, middleware, WebSocket
├── tests/                 # Юнит-тесты, структурированные по типам конвертеров
│   └── tests_convertors/
├── converted_files/       # Volume для выходных файлов (монтируется в Docker)
└── uploaded_files/        # Volume для исходных файлов (монтируется в Docker)

### Реализованный функционал

* **Аутентификация:** Использование **обычных токенов** для защиты основных эндпоинтов.
* **Обработка файлов:** Прием файлов через `fastapi.UploadFile`, сохранение и постановка задачи в очередь RQ.
* **WebSocket:** Реализован эндпоинт `/wss/progress` для имитации и отслеживания прогресса конвертации в реальном времени.
* **Собственная обработка исключений:** Кастомные обработчики ошибок (<code>401 Unauthorized</code>, <code>404 Not Found</code>) с возвратом пользователю HTML-страниц.
